Минимальная и расширяемая тема zsh.

Установка
Руководство:

Получите копию minimal.zshи источник, например:

curl -O ~/minimal.zsh https://raw.githubusercontent.com/subnixr/minimal/master/minimal.zsh
source ~/minimal.zsh
Зген :

zgen load subnixr/minimal
Антиген :

antigen bundle subnixr/minimal
О, мой Зш :

git clone https://github.com/subnixr/minimal.git  ${ZSH_CUSTOM}/themes/minimal

ln -s ${ZSH_CUSTOM}/themes/minimal/minimal.zsh ${ZSH_CUSTOM}/themes/minimal.zsh-theme
# then update `ZSH_THEME` to `minimal` in your .zshrc 
Инжир :

minimalтакже доступно на рис.


Настройка и расширение
Архитектура
Minimal по сути представляет собой набор компонентов (функций оболочки) поверх тонкого слоя для облегчения настройки.

Существует 3 области, в которых можно визуализировать компонент:

левая подсказка
правильная подсказка
информационная строка (отображается, когда нет команды и пользователь нажимает Enter)
Компонент должен работать в любой из трех областей (слева, справа, информация)

Переопределить настройки по умолчанию
Различные компоненты могут использовать эти (глобальные) настройки:

MNML_OK_COLOR: Цвет для успешных дел (по умолчанию: 2)
MNML_ERR_COLOR: Цвет для сбоев (по умолчанию: 1)
MNML_BGJOB_MODE: Режим применяется при наличии фоновых заданий (по умолчанию: 4)
MNML_USER_CHAR: Символ, используемый для непривилегированных пользователей (по умолчанию: )
MNML_INSERT_CHAR: Символ, используемый для режима вставки vi (по умолчанию: ›)
MNML_NORMAL_CHAR: Символ, используемый для обычного режима vi (по умолчанию: ·)
MNML_ELLIPSIS_CHAR: Символ, используемый при усечении длинных слов (по умолчанию: ..)
Три глобальных массива управляют определением и позицией рендеринга компонентов:

# Components on the left prompt
MNML_PROMPT=(mnml_ssh mnml_pyenv mnml_status mnml_keymap)

# Components on the right prompt
MNML_RPROMPT=('mnml_cwd 2 0' mnml_git)

# Components shown on info line
MNML_INFOLN=(mnml_err mnml_jobs mnml_uhp mnml_files)
Для настройки поведения магического ввода используется дополнительный массив:

MNML_MAGICENTER=(mnml_me_dirs mnml_me_ls mnml_me_git)
Эти значения можно изменить интерактивно или в любом из файлов init.

PROMPTи их RPROMPTследует оставить нетронутыми, так как минимальный уход уже обеспечивает их.

Доступные компоненты
Статус
?

Синтаксис :mnml_status

Индикатор, отображающий следующую информацию:

привилегия пользователя: #выводится, если пользователь root, $MNML_USER_CHARв противном случае.
последняя команда выполнена успешно: цвет индикатора устанавливается таким, $MNML_OK_COLORкакой был при успешном выполнении последней команды, $MNML_ERR_COLORв противном случае.
фоновые задания: $MNML_BGJOB_MODEприменяется к индикатору, если хотя бы одно задание находится в фоновом режиме.
Раскладка клавиатуры
›

Синтаксис :mnml_keymap

Индикатор, отображающий текущую раскладку клавиатуры, $MNML_INSERT_CHARпечатается в режиме вставки или по умолчанию, $MNML_NORMAL_CHARв обычном режиме (vi).

Реагирует на изменения раскладки клавиатуры. Должен работать, даже если режим привязки zsh не установлен наvi

Текущий рабочий директор
~

Синтаксис :mnml_cwd N LEN

Отображает последние Nсегменты текущего рабочего каталога, каждый из которых усекается при LENего превышении.

Если Nуказано 0, будут отображены все сегменты. Если Nне указано, будет использовано значение по умолчанию 2. Если указано , но N <= 0, будет использовано значение 0.

Если LENне указано или LEN <= 0не указано, усечение сегментов не производится. Если 0 < LEN < 4задано значение 4.

Если длина сегмента больше LENзначения , LEN / 2 - 1печатаются первые символы, затем $MNML_ELLIPSIS_CHAR, а затем последние LEN / 2 - 1символы. Например, с LEN = 8и 0123456789в качестве сегмента 012..789отображается .

Статус ветки Git
master

Синтаксис :mnml_git

Отображает текущую ветку Git внутри репозитория Git. Цвет меняется на , $MNML_OK_COLORесли ветка чистая, $MNML_ERR_COLORи на , если ветка грязная.

Статус отделения Mercurial
default

Синтаксис :mnml_hg

Отображает текущую ветку Mercurial в репозитории Mercurial. Цвет устанавливается равным , $MNML_OK_COLORесли ветка чистая, и $MNML_ERR_COLOR, если ветка грязная.

Этот компонент по умолчанию отключен, MNML_RPROMPTно если вы хотите включить его, просто переопределите конфигурацию по умолчанию, например, с помощью MNML_RPROMPT=('mnml_cwd 2 0' mnml_git mnml_hg).

Если вы считаете, что этот компонент работает немного медленно, вы можете использовать mnml_hg_no_colorвспомогательный компонент, который не запускает новый интерпретатор Python, что означает отсутствие поддержки цветов, если ветка изменена; этот компонент просто отображает имя текущей ветки.

Пользователь, имя хоста и пароль
user@host:~

Синтаксис :mnml_uhp

Отображает текущее имя пользователя, имя хоста и рабочий каталог.

Имя хоста SSH
host

Синтаксис :mnml_ssh

Отображает имя хоста только в том случае, если текущий сеанс осуществляется через SSH-соединение.

виртуальная среда Python
venv

Синтаксис :mnml_pyenv

Отображает текущую активированную среду Python virtualenv.

Значение ошибки последней команды
1

Синтаксис :mnml_err

Отображает статус выхода последней команды только в том случае, если это не 0.

Счетчик фоновых заданий
2&

Синтаксис :mnml_jobs

Отображает количество фоновых заданий только в том случае, если есть хотя бы одно.

Пользовательские компоненты
Добавление функциональности так же просто, как написание функции оболочки и добавление ее в один из массивов:

function awesome_component {
  echo -n "AWESOME"
}

function awesome_magicenter {
  figlet -f slant "COOL"
}

source minimal.zsh

MNML_PROMPT=(awesome_component $MNML_PROMPT)
MNML_MAGICENTER+=awesome_magicenter
Из-за минимальной архитектуры, если вам нужно значение статуса выхода последней команды ( $?), $MNML_LAST_ERRнеобходимо использовать . $?Его по-прежнему можно использовать для проверки ошибок внутри компонента.
