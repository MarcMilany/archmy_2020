Как настроить брандмауэр с помощью `nftables` в Arch Linux

Ибрагим Коруджоглу ( @siberoloji ) | Воскресенье, 13 апреля 2025 г.

https://www.siberoloji.com/arch-linux-howtos-configure-a-firewall-with-nftables/

В этом руководстве мы рассмотрим всё необходимое для настройки и запуска брандмауэра nftables в Arch Linux. Мы рассмотрим установку, основные понятия, создание наборов правил, сохранение и устранение неполадок.
Убедитесь, что у вас есть:
Работающая установка Arch Linux.
Права root или пользователя с sudo доступом.
Базовое понимание сетевых концепций.


При обеспечении безопасности системы Linux одним из основных этапов является настройка межсетевого экрана. В Arch Linux для этой задачи используется современный и рекомендуемый инструмент nftables— мощный и гибкий фреймворк фильтрации пакетов, разработанный в рамках проекта Netfilter. Он заменяет устаревшие системы, такие как iptables, ip6tables, arptablesи ebtables, обеспечивая унифицированный и эффективный подход к управлению сетевым трафиком.

Зачем использовать nftables?
Прежде чем углубляться, давайте кратко рассмотрим, почему nftables он предпочтительнее устаревших инструментов: Унифицированная структура: в отличие от предыдущих инструментов, которым требовались отдельные утилиты для мостов IPv4, IPv6, ARP и Ethernet, nftablesобъединяет все. Упрощенный синтаксис: синтаксис правил более удобочитаем и прост в управлении. Лучшая производительность: более эффективное использование памяти и скорость обработки. Атомарные обновления правил: правила обновляются атомарно, что снижает риск потери пакетов во время перезагрузки. Улучшенное ведение журнала и отладка: отладка стала проще благодаря структурированным сообщениям об ошибках и улучшенной поддержке ведения журнала.

Шаг 1: Установкаn ftables
В большинстве установок Arch Linux он уже установлен nftablesпо умолчанию. Чтобы проверить, установлен ли он:
nft --version
Если он не установлен, вы можете установить его с помощью:
sudo pacman -S nftables

Шаг 2: Включение nftablesслужбы
Чтобы убедиться, что ваш брандмауэр запускается при загрузке системы, включите службу systemd:
sudo systemctl enable nftables.service
sudo systemctl start nftables.service
Чтобы убедиться, что он работает:
sudo systemctl status nftables.service

Шаг 3: Понимание nftables концепций
Прежде чем настраивать набор правил, полезно понять некоторые основные концепции nftables.

Таблицы: Таблицы являются контейнерами для правил и могут быть следующих типов:
ip– только IPv4
ip6– только IPv6
inet– как IPv4, так и IPv6 (рекомендуется для большинства случаев использования)

Цепи: Цепочки определяют точки на пути обработки пакетов, где оцениваются правила, например:
input– пакеты, предназначенные для локальной системы
output– пакеты, отправленные из локальной системы
forward– пакеты, проходящие через систему

Правила: Правила определяют действия, предпринимаемые над пакетами, соответствующими заданным условиям. Примеры включают разрешение или отбрасывание пакетов, их регистрацию в журнале или переход на другую цепочку.

Шаг 4: Создание базового набора правил брандмауэра
Давайте создадим базовый набор правил, чтобы разрешить необходимый трафик и запретить все остальное.
1. Создайте новый файл для определения вашего набора правил.
sudo nano /etc/nftables.conf
2. Добавьте следующую базовую конфигурацию
#!/usr/sbin/nft -f

table inet filter {
  chain input {
    type filter hook input priority 0;
    policy drop;

    # Allow loopback
    iif lo accept

    # Allow established and related connections
    ct state established,related accept

    # Allow SSH
    tcp dport 22 ct state new accept

    # Allow ICMP (ping)
    ip protocol icmp accept
    ip6 nexthdr icmpv6 accept

    # Log and drop everything else (optional)
    log prefix "nftables input drop: " flags all counter
    drop
  }

  chain forward {
    type filter hook forward priority 0;
    policy drop;
  }

  chain output {
    type filter hook output priority 0;
    policy accept;
  }
}

3. Сохраните и выйдите из файла.

4. Проверьте синтаксис конфигурации.
sudo nft -c -f /etc/nftables.conf
Если ошибок не обнаружено, загрузите правила:
sudo nft -f /etc/nftables.conf

Для проверки активных правил:
sudo nft list ruleset

Шаг 5: Обеспечение постоянных правил
nftables.service По умолчанию он загружается /etc/nftables.conf при запуске. Поэтому, как только ваши правила будут правильно определены в этом файле и служба будет включена, ваш брандмауэр сохранится после перезагрузки.
Вы можете проверить это, перезагрузив систему и выполнив:
sudo nft list ruleset

Шаг 6: Разрешение на использование дополнительных услуг
Если в вашей системе запущены дополнительные службы (например, веб-сервер или DNS-преобразователь), вам необходимо явно разрешить их.
Вот несколько примеров:

    # Allow HTTP and HTTPS
    tcp dport { 80, 443 } ct state new accept

    # Allow DNS
    udp dport 53 ct state new accept
Просто вставьте эти строки в input цепочку внутри /etc/nftables.conf.

Шаг 7: Регистрация потерянных пакетов
Для отладки или аудита может потребоваться ведение журнала потерянных пакетов. Базовая конфигурация уже включает правило журналирования:
log prefix "nftables input drop: " flags all counter
Журналы можно найти с помощью:
sudo journalctl -k | grep nftables
Помните, что чрезмерное ведение журналов (особенно с помощью flags all) может быстро привести к переполнению журналов, поэтому используйте его с осторожностью в производственных средах.

Шаг 8: Очистка и сброс правил
Чтобы очистить все активные правила:
sudo nft flush ruleset

Это очистит все таблицы, цепочки и правила, находящиеся в данный момент в памяти, но не повлияет на ваш /etc/nftables.conf.
Чтобы перезагрузить сохраненную конфигурацию:
sudo nft -f /etc/nftables.conf

Шаг 9: Дополнительные советы
Именованные наборы
Для упрощения управления сложными правилами используйте именованные наборы. Например:

set trusted_ips {
  type ipv4_addr
  elements = { 192.168.1.10, 192.168.1.11 }
}

ip saddr @trusted_ips accept

Ограничение скорости
Предотвратите атаки методом подбора с помощью ограничения скорости:
tcp dport 22 ct state new limit rate 10/minute accept

Отдельные цепочки для услуг
Для лучшей организации:

chain ssh_chain {
  tcp dport 22 ct state new accept
}

chain input {
  ...
  jump ssh_chain
  ...
}

Шаг 10: Устранение неполадок
Вот некоторые распространенные ошибки и способы их устранения:

SSH заблокирован : всегда держите терминал открытым с доступом по SSH при тестировании новых правил. Используйте limit или разрешите определённые IP-адреса, чтобы снизить риск подбора паролей.
Правила не загружаются после перезагрузки : убедитесь, /etc/nftables.conf что они правильно настроены и nftables.service включены.
Ошибки синтаксиса : используйте nft -c -f для проверки конфигурации перед загрузкой.
Нет регистрации : проверьте, регистрирует ли ваша система сообщения ядра ( journalctl -k). Возможно, вам также потребуется настроить параметры ядра rsyslog или .journald

Заключение:
nftables Arch Linux предоставляет мощный и в то же время элегантный способ управления правилами брандмауэра для вашей системы. Благодаря унифицированной конфигурации, понятному синтаксису и современным функциям, таким как именованные наборы и ограничение скорости, обеспечить эффективную защиту системы становится проще, чем когда-либо.
Определив простой, но строгий набор правил, разрешив только необходимые службы и обеспечив постоянство настроек, вы обеспечите защиту своей системы как сейчас, так и после каждой перезагрузки. Это руководство поможет вам адаптировать конфигурацию брандмауэра по мере роста ваших потребностей.
